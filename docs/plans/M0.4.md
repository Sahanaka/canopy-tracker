# Plan — M0.4 Field form spec

## Goal

Define the QField form and the GeoJSON schema for field points, and add `highland.io.load_field_points()`, which
validates committed field files and reports every problem at once. Field points feed M1.9 (mapped vs observed
disturbance, confusion table) and M2.3 (Random Forest training labels).

Acceptance criteria (docs/ROADMAP.md):
- `docs/field/form.md` describing the QField form (fields: class, canopy openness, photos, notes, date) and the
  expected GeoJSON schema.
- `highland.io.load_field_points()` that validates that schema; tests with a fixture file.

## Data

No satellite data. Sources checked 2026-11-01:
- **QField attachments:** the Attachment widget stores photos; "by default, pictures are saved into the 'DCIM' folder
  ... with a timestamp as name"; extra attachment paths "evaluate relative to the project directory".
  https://docs.qfield.org/how-to/project-setup/pictures/ . The exact default filename pattern is not documented; Step 1
  records what QField writes on the owner's device. The QGIS widget must be set to "relative to project path".
- **QField position variables:** `@position_horizontal_accuracy` = "horizontal accuracy of the coordinate (in
  meters), as reported by the sensor"; it is NULL when the crosshair is moved by hand, and `@position_source_name` is
  then "manual". `@gnss_horizontal_accuracy` always reports the sensor. `@position_timestamp` is UTC.
  `@cloud_username` gives the QFieldCloud user. https://docs.qfield.org/reference/expression_variables/
- **Offline format:** QField edits a GeoPackage working copy; QFieldSync/QFieldCloud sync it back to the QGIS project.
  https://qfield.org/docs/qfieldsync/index.html ,
  https://docs.qfield.org/get-started/tutorials/advanced-setup-qfc/
- **GeoJSON export:** QGIS Export → Save Features As → GeoJSON, CRS EPSG:4326, layer option `RFC7946=YES` (GDAL
  driver: WGS84 coordinates, 7 decimals by default ≈ 1 cm). https://gdal.org/en/stable/drivers/vector/geojson.html ,
  https://docs.qgis.org/latest/en/docs/user_manual/managing_data_source/create_layers.html
  GDAL does not document the DateTime text format it writes; Step 1 probes it (offset kept or dropped).
- **Canopy openness method (option):** GLAMA computes a canopy-cover index from smartphone hemispherical photos;
  Tichý 2016, J. Veg. Sci. 27:427–435, doi:10.1111/jvs.12350; https://www.sci.muni.cz/botany/glama/ . An Ohio
  comparison found large differences between smartphone apps (https://peerj.com/articles/13450), so app values are
  not interchangeable.
- **Bounds:** `data/aoi/aoi.geojson` (absent today) via `highland.aoi.load_aoi()`; fallback `SRI_LANKA_BBOX` (ADR 0007).

## Design

`docs/field/form.md` (owner-facing): QGIS layer setup (GeoPackage point layer, EPSG:4326, widgets and defaults
below), QField use, photo handling, export to GeoJSON, `python -m highland.io <file>` to validate, privacy rules.
Schema (property names are the contract; codes stored, labels shown by Value Map widgets):

| field | type | req | QField widget / default | allowed values |
|---|---|---|---|---|
| `point_id` | text | yes | Text, default `uuid()` (not editable) | unique across all files |
| `observed_at` | text, ISO 8601 with offset | yes | default `format_date(now(), 'yyyy-MM-ddTHH:mm:ss') \|\| '+05:30'` (Step 1 verifies) | parseable, not in future |
| `observer` | text | yes | default `@cloud_username`, editable | initials/handle only, never a full name |
| `class` | text | yes | Value Map | `pine`, `turpentine`, `eucalyptus`, `native_broadleaf`, `alstonia`, `tea`, `grassland`, `settlement`, `other`, `unsure` (D2) |
| `secondary_class` | text | no | Value Map | same list or empty (e.g. *Alstonia* under opened pine) |
| `opened` | text | yes | Value Map | `yes`, `no`, `unsure` — canopy recently opened at this point (D3) |
| `patch_id` | text | no | Text | M1.7 patch id when visiting a mapped patch |
| `canopy_open_pct` | integer | yes | Range 0–100 | 0–100; 100 − vertical canopy cover (D4) |
| `openness_method` | text | yes | Value Map, default `visual` | `visual`, `glama` |
| `photo_1`..`photo_3` | text | no | Attachment, relative to project | relative path, `/` separators, no `..`, `.jpg/.jpeg/.png` (D6) |
| `gps_accuracy_m` | real | no | default `@position_horizontal_accuracy` | ≥ 0 or null |
| `position_source` | text | no | default `@position_source_name` | free text (`manual` flags hand-placed points) |
| `notes` | text | no | Text (multiline) | free text |

`src/highland/io.py`:
- `class FieldDataError(ValueError)`: carries `problems: list[str]`; message lists all, each "file, point_id/row: rule,
  value". Module constants `FIELD_CLASSES`, `OPENED_VALUES`, `OPENNESS_METHODS`, `REQUIRED_FIELDS`, and
  `OTHER_GROUP = {"tea", "grassland", "settlement", "other"}` (collapse to M2.3 "other").
- `default_field_dir() -> Path` (repo-relative like `default_aoi_path`).
- `load_field_points(paths: str | Path | Sequence[str | Path] | None = None, *, aoi: gpd.GeoDataFrame | None = None,
  photo_root: str | Path | None = None, now: datetime | None = None) -> gpd.GeoDataFrame` — returns points in
  EPSG:4326 (degrees) with typed columns: categoricals for codes, `canopy_open_pct` `Int16`, `gps_accuracy_m`
  `Float32`, `observed_at` tz-aware UTC, `photos` list column, `source_file` str. Default: all
  `data/field/*.geojson` plus `data/field/private/*.geojson` if present (D7). Order of checks: file readable →
  CRS WGS84 geographic (same datum rule as ADR 0007) → then per-row checks, all collected: Point (drop Z; reject
  Multi/empty), lon/lat degrees + swapped hint, inside AOI polygon (or bbox fallback with WARNING log, D8),
  required fields non-null, allowed values, integer range, datetime parseable with offset and ≤ `now`, unique
  `point_id`, no exact duplicate (geometry + `observed_at`), photo paths well-formed and, if `photo_root` given,
  existing. Unknown extra properties are kept and logged at INFO, not rejected.
- `main(argv) -> int`: `python -m highland.io [paths...]` prints counts by class/opened or the full problem list;
  exit 0/1. Never edits files (prompt 03).
- `.gitignore`: `data/field/private/` and `data/field/photos/`. `data/field/README.md`: one paragraph linking form.md.
- `docs/decisions/0008-field-data-schema.md`: D1–D8. No notebook, no `outputs/`.

## Science checks

- **Never invent observations/thresholds:** only vocabulary and value ranges are defined. No GPS-accuracy cut-off and
  no openness class breaks are set here; any accuracy filter for M1.9/M2.3 is a later ADR. `unsure` exists so the
  owner never has to guess a class.
- **Module B classes:** codes match CLAUDE.md; *Alstonia macrophylla* is labelled invasive in form.md; `OTHER_GROUP`
  keeps the split reversible for M2.3.
- **WorldCover/forest-mask gotcha:** `opened=yes` points on grass/scrub are exactly the signal WorldCover hides;
  form.md asks for `class` = what is there now and `opened` = evidence of removal (stumps, slash), so M1.9 can use both.
- **AOI constraint:** no coordinates in code; fixtures use synthetic points inside a synthetic AOI fixture.
- **CRS:** stored EPSG:4326; reprojection to EPSG:32644 is left to callers (`highland.aoi.to_utm`).
- SCL, Landsat, index and terrain gotchas do not apply.

## Decisions needed

- **D1 Input format.** (a) GeoJSON only, exported from QGIS with RFC7946=YES. (b) Also read the QField GeoPackage
  directly. **Recommend (a)**: roadmap says GeoJSON, text diffs review well in a public repo; the reader is
  OGR-based so (b) can be added later without schema change.
- **D2 Class vocabulary.** (a) Six codes with a single `other`. (b) Split other into `tea`, `grassland`,
  `settlement`, `other`, plus `unsure`, and optional `secondary_class`. **Recommend (b)**: cheap in the field,
  collapsible via `OTHER_GROUP`, and tea/grass errors matter for Module A.
- **D3 Disturbance status.** (a) `opened` yes/no/unsure required, `patch_id` optional. (b) Add a
  `disturbance_type` vocabulary (felled/thinned/burnt/landslide). **Recommend (a)**; types go in `notes` until
  M1.10 shows they are needed.
- **D4 Canopy openness.** (a) Visual % estimate 0–100 (100 − vertical cover), coarse and observer-dependent.
  (b) Ordinal classes (break values would need an ADR and a source). (c) GLAMA reading only. **Recommend (a) with
  `openness_method` allowing `glama`** when the owner has time; form.md states precision honestly and advises
  rounding to the nearest 5–10 %, and that visual and GLAMA values are not pooled without a check.
- **D5 Date/time.** (a) Local time with explicit `+05:30` offset, returned as UTC; naive values rejected.
  (b) Naive values accepted and assumed Asia/Colombo with a warning. (c) UTC from `@position_timestamp`.
  **Recommend (a)**; (c) is NULL for hand-placed points.
- **D6 Photos.** (a) Three Attachment fields `photo_1..3`, relative paths; photo files kept out of git
  (`data/field/photos/`, ignored) because EXIF GPS can expose locations and size grows fast. (b) One `;`-joined
  field. **Recommend (a)**.
- **D7 Location privacy.** (a) Never record homes; points on private land go to git-ignored
  `data/field/private/*.geojson` (same schema), loaded for analysis, never committed or shown in the viewer.
  (b) A `private` flag in the public file plus rounding for publication — the raw coordinates would still be public.
  **Recommend (a)**; analysis always uses unrounded coordinates.
- **D8 Bounds and error strategy.** Inside the AOI polygon if `data/aoi/aoi.geojson` exists, else Sri Lanka bbox with
  a WARNING; points outside are errors. Collect all row problems into one `FieldDataError`; only unreadable files
  or a wrong CRS stop early. **Recommend as stated.**

## Risks

- QField/GDAL datetime round-trip may drop the offset or change the format; Step 1 probes and the plan is amended.
- QField's default photo filename and folder vary by version/device (forum reports); form.md tells the owner to check
  one exported row before a full trip.
- `@cloud_username` is empty without QFieldCloud; the default must stay editable.
- Visual openness estimates are subjective; M1.9 must report them as such, not as measurements.
- Private-file split relies on the owner choosing the right file in the field; form.md gives a one-line rule.

## Deviations

- **Step 1 probe (GDAL 3.13.3, pyogrio 0.13.0):** writing a tz-aware datetime keeps the offset
  (`2026-05-01T10:00:00+05:30`); text with an offset reads back as tz-aware by default, but the loader reads with
  `datetime_as_string=True` (offset and `Z` preserved verbatim) and parses with `datetime.fromisoformat`, so naive
  and mixed values can be rejected per row. Integer fields read as int32 (float64 when a value like 33.5 is present,
  hence the whole-number check). 3-D points are labelled EPSG:4979 (datum rule handles it); a legacy `crs` member
  (EPSG:32644) is honoured; a zero-byte file raises `DataSourceError`; an empty FeatureCollection reads as 0 rows.
  Confirmed in the QGIS 3.44 function list: `uuid([format])` with `'WithoutBraces'`, and `format_date`. The plan's
  `uuid()` returns braces, so the form uses `uuid('WithoutBraces')`. The default `observed_at` expression uses
  `replace(format_date(now(), 'yyyy-MM-dd HH:mm:ss'), ' ', 'T') || '+05:30'` to avoid quoting `T`; not run on a device.
- **QField photo filename pattern:** not determinable here (no device; docs only say a timestamp name in DCIM). form.md
  tells the owner to check one exported row.
- **Extra fixtures/tests beyond the plan:** `bad_vocab`, `no_features`, split `duplicate_id_a/b`; a same-place-and-time
  duplicate test built in `tmp_path`. `main` gained `--photo-root`.
- **Sri Lanka bbox for the swapped check** uses `highland.aoi.SRI_LANKA_BBOX` (reused, not duplicated).
- **Empty `data/field/` + no paths:** `load_field_points()` raises `FileNotFoundError` with an owner-friendly message.

## Review loop 1

Science review asked for changes; all applied (no numeric thresholds added; open decisions are listed in ADR 0008):
- Vocabulary values are stored stripped (padded `" pine"` no longer becomes NaN); the loader raises if a required categorical ends up NaN.
- New columns: `private` (bool) and `source_file` relative to `data/field/`; prompt 03 step 4 now says private points never go to the viewer.
- New: `REFERENCE_CLASSES`, `opened_years_ago` (only when `opened = yes`), `openness_method = not_measured` (with empty `canopy_open_pct`, required otherwise), optional `gps_time_utc`; `secondary_class` may not equal `class` or be `unsure`.
- `form.md` and ADR 0008 updated (spatial support, operational classes, per-method openness, unsure policy, sampling bias, clock risk, GPS decision owner); leftover `if True` removed.
