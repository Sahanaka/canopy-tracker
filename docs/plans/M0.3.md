# Plan — M0.3 AOI

## Goal

Add `highland.aoi.load_aoi()`, which loads `data/aoi/aoi.geojson`, checks it against explicit sourced rules and
returns it with a CRS attached. Add a UTM reprojection helper, synthetic tests and instructions for drawing the AOI.

Acceptance criteria (docs/ROADMAP.md):
- Owner commits `data/aoi/aoi.geojson`. Agent adds `highland.aoi.load_aoi()` that validates: single polygon,
  EPSG:4326, area 50–200 km², inside Sri Lanka's bounding box; with tests.

The first criterion is the owner's job. The task is ticked only after the owner commits the file and it passes the
validator. The agent's work can merge before that, with the task left unticked.

## Data

No satellite data is used. Sources were checked on 2026-11-01.
- **GeoJSON CRS (RFC 7946):** https://www.rfc-editor.org/rfc/rfc7946
  - §4: coordinates are WGS 84 in decimal degrees. App. B.1: the 2008 `crs` member "is no longer used".
  - §3.1.1: positions are ordered longitude, then latitude.
  - §3.1.6: rings "MUST follow the right-hand rule", but "parsers SHOULD NOT reject Polygons that do not follow the
    right-hand rule".
- **Sri Lanka bounding box:** EPSG area of use "Sri Lanka - onshore" (the area of EPSG:5235 SLD99 / Sri Lanka Grid
  1999): W 79.64, S 5.86, E 81.95, N 9.88. https://spatialreference.org/ref/epsg/5235/
  - Cross-check, MFA Sri Lanka: 5°55'–9°51' N, 79°41'–81°53' E. https://www.mfa.gov.lk/national-profile-and-geography
  - Not used: Natural Earth 110m (79.695, 5.968, 81.788, 9.824) is too coarse and cuts the coast.
    https://gist.github.com/graydon/11198540
  - The EPSG box comes from a registry and is shipped offline in pyproj's PROJ db, so a test can read it from there.
- **Working CRS:** EPSG:32644, area of use 78–84°E, equator to 84°N. https://spatialreference.org/ref/epsg/32644/
  UTM uses k0 = 0.9996, and zone 44 has its central meridian at 81°E (Snyder 1987, USGS PP 1395, UTM chapter).
  All of Sri Lanka lies within 1.4° of 81°E. Point scale k ≈ k0·(1 + (Δλ·cosφ)²/2) runs from 0.9996 to about
  0.9999, so planar UTM area is 0.02–0.08 % below true ellipsoidal area. At 200 km² that is at most 0.16 km².
  The implementer confirms k0 and the central meridian from `pyproj.CRS("EPSG:32644")` in Step 1.
- **Area bounds 50–200 km²** are the owner's numbers from the roadmap. The AOI is described as about 10 × 10 km.

## Design

`src/highland/aoi.py`:
- `class AOIError(ValueError)`: raised for any validation failure. The message names the rule and the measured value.
- `SRI_LANKA_BBOX: tuple[float, float, float, float] = (79.64, 5.86, 81.95, 9.88)` in lon/lat degrees, citing
  EPSG:5235 in a comment. Also `AREA_KM2_RANGE = (50.0, 200.0)`, `WORK_CRS = "EPSG:32644"`, `AOI_CRS = "EPSG:4326"`.
- `default_aoi_path() -> Path`: returns `Path(__file__).resolve().parents[2] / "data" / "aoi" / "aoi.geojson"`.
  This does not depend on the working directory. It is valid for the editable install that README/ADR 0004 prescribe
  (D5).
- `load_aoi(path: str | Path | None = None) -> geopandas.GeoDataFrame`: returns one row with a Polygon in
  EPSG:4326 (degrees). Properties are kept. The checks run in this order:
  1. If the file is missing, raise `FileNotFoundError` with a message pointing to `data/aoi/README.md`.
  2. Read with `geopandas.read_file` (pyogrio). Read errors, a 0-byte file or 0 features raise `AOIError`.
     FeatureCollection, Feature and bare geometry objects are accepted if GDAL reads them (confirmed in Step 1).
  3. Exactly one feature is required. Several features are never dissolved.
  4. CRS: `gdf.crs` must be equivalent to EPSG:4326 / OGC:CRS84, compared by datum and units, not by axis order.
     A legacy `crs` member that GDAL honours (for example EPSG:32644) raises `AOIError` with the text "re-export as
     EPSG:4326". It is not reprojected silently (D4).
  5. Geometry: drop Z with `shapely.force_2d`. The geometry must be non-empty, valid (`is_valid`; the error carries
     `explain_validity`, and there is no auto `make_valid`) and have no interior rings. A MultiPolygon with exactly
     one part is unwrapped to a Polygon. Any other type is rejected (D3).
  6. Coordinate sanity: all bounds must fall within ±180 / ±90. Projected metres fail here.
  7. Containment: the bounds must lie inside `SRI_LANKA_BBOX`. If they fail, retry with axes swapped. If the swapped
     bounds fit, the message says "lon/lat look swapped".
  8. Area: `to_utm(gdf).area / 1e6` must fall within `AREA_KM2_RANGE` (D1).
  9. Ring orientation: normalise to a counter-clockwise exterior with `shapely.orient_polygons`. This step never
     rejects and never warns (D3).
  Log the area (km²) and the bounds at INFO with `logging.getLogger(__name__)`.
- `to_utm(aoi: geopandas.GeoDataFrame) -> geopandas.GeoDataFrame`: reprojects to EPSG:32644 (metres).
- `aoi_area_km2(aoi: geopandas.GeoDataFrame) -> float`: returns the planar area in EPSG:32644, in km².
- `main(argv: list[str] | None = None) -> int` with `if __name__ == "__main__"`. `python -m highland.aoi [path]`
  prints the area, bounds and "OK", or the error, and exits 0 or 1. This is the owner's validator.
- `data/aoi/README.md` (D6): how to draw and validate the AOI. It covers:
  - geojson.io: draw one polygon, then Save → GeoJSON.
  - QGIS: a polygon layer, then Export → Save Features As → GeoJSON, CRS EPSG:4326, layer option `RFC7946=YES`.
  - Rules: one polygon, no holes, about 10 × 10 km (50–200 km²). Save as `data/aoi/aoi.geojson`.
  - Then run `python -m highland.aoi`, commit and open a PR.
- `docs/decisions/0007-aoi-validation.md`: records D1–D6, including the bounding box source.
- No notebook. No `outputs/` files.

## Science checks

- **AOI hard constraint:** coordinates live only in the AOI file. The package holds only the cited country box as a
  validation constant. Test fixtures are synthetic squares, not the real AOI.
- **CRS convention:** the AOI is stored in EPSG:4326 and work happens in EPSG:32644. Area is never computed in
  degrees. UTM error over Sri Lanka is at most 0.08 % (see Data).
- **No invented thresholds:** 50–200 km² comes from the roadmap. The bounding box comes from the EPSG registry.
  Both are recorded in ADR 0007.
- The SCL, Landsat, index and terrain gotchas do not apply.

## Tests

`tests/test_aoi.py`: no network. It uses only `tests/fixtures/aoi/*.geojson`, small hand-written files with
synthetic squares inside the country box.
- **Valid cases:**
  - `valid.geojson`, a FeatureCollection with a square of about 100 km².
  - `feature.geojson` and `bare_geometry.geojson` (if GDAL reads them).
  - `multipolygon_one_part`, `clockwise_ring` and `with_z`, each also with extra properties.
  - Each returns one row with a Polygon in EPSG:4326. The output exterior is counter-clockwise.
- **Invalid cases** raise `AOIError`, and the test checks the message:
  - `empty_file` (0 bytes), `empty_fc`, `two_features`, `multipolygon_two_parts`, `point`, `bowtie`
    (self-intersecting), `with_hole`.
  - `too_small` (about 16 km²), `too_large` (about 400 km²).
  - `outside_sri_lanka` (inside zone 44 but off the island), `swapped_latlon` (message says "swapped").
  - `projected_coords` (UTM metres without a `crs` member), `legacy_crs_32644`.
  - A missing path raises `FileNotFoundError`.
- `aoi_area_km2(valid)` agrees with `pyproj.Geod(ellps="WGS84").geometry_area_perimeter` within 0.1 %.
- `SRI_LANKA_BBOX` equals `pyproj.CRS("EPSG:5235").area_of_use.bounds` to within 0.01°. This reads the local PROJ db,
  not the network. The test also checks that the box lies inside 78–84°E, which makes a separate zone check
  unnecessary (D2).
- `default_aoi_path()` is absolute and ends in `data/aoi/aoi.geojson`. It is unchanged after `monkeypatch.chdir(tmp_path)`.
- `main([valid])` returns 0 and `main([too_small])` returns 1 (use `capsys`).
- `tests/test_aoi_file.py` (D7): validates the real `data/aoi/aoi.geojson`, and skips with a reason while the file
  is absent. It has no marker, so CI runs it once the owner commits the file.

## Decisions needed

- **D1 Area method.** (a) Planar area in EPSG:32644, the project CRS. The bias is −0.02 % to −0.08 % over Sri Lanka.
  (b) Geodesic area on the WGS84 ellipsoid with `pyproj.Geod`, which is exact. (c) An equal-area CRS such as
  EPSG:6933, a third CRS. **Recommend (a)**, so the AOI area matches every later area figure in the project. (b) is
  used as a test cross-check.
- **D2 Country box and buffer.** (a) EPSG:5235 area of use (79.64, 5.86, 81.95, 9.88) with no buffer. (b) Natural
  Earth 10m or GADM extent, which needs a download to cite exactly. (c) Option (a) plus a 0.1° buffer.
  **Recommend (a)**: it is a registry value, testable offline, and the AOI is inland so a buffer adds nothing.
  No separate UTM-44 check, because the box lies inside 78–84°E and a test asserts this.
- **D3 Geometry leniency.** Recommend these rules:
  - Accept a one-part MultiPolygon (QGIS often exports one) and unwrap it.
  - Reject holes and multi-part geometries.
  - Reject invalid geometry, with no auto-repair, because `make_valid` can change the area.
  - Drop Z coordinates.
  - Ring orientation: normalise silently, with no warning or rejection, as RFC 7946 §3.1.6 asks of parsers.
  The alternative is a strict mode that rejects anything that is not already a clean Polygon.
- **D4 Wrong declared CRS.** (a) Reject and tell the owner to re-export. (b) Reproject to 4326 automatically.
  **Recommend (a)**: the roadmap says to validate EPSG:4326, and RFC 7946 has no `crs` member.
- **D5 Default path.** (a) A repo-relative path from `__file__`. It works for the editable install that the project
  prescribes; for other installs, pass `path=` explicitly. (b) Option (a) plus a `HIGHLAND_AOI` env-var override.
  **Recommend (a)**. Add (b) only if a non-editable use case appears.
- **D6 Owner instructions.** (a) `data/aoi/README.md`, next to the file. (b) A section in the top-level README.
  **Recommend (a)**, with a one-line link from the README's "How to run".
- **D7 Real-file test.** (a) An unmarked test that skips while the file is absent, so CI guards the committed AOI.
  (b) No test, CLI only. (c) A `network`-marked test, which is wrong because the test needs no network.
  **Recommend (a)**.

## Risks

- GDAL handling of bare geometries, Feature objects, legacy `crs` members and 0-byte files varies by version. Step 1
  probes the pinned pyogrio/GDAL and the tests pin the observed behaviour. If behaviour differs, the plan is amended.
- The `crs.equals` comparison of EPSG:4326 with OGC:CRS84 can fail on axis order. The check compares datum and units.
- The CI skip of `test_aoi_file.py` hides nothing today. Once the file exists, a bad edit fails CI, which is intended.
- The owner may draw an AOI that crosses outside 50–200 km². The error states the measured area. The bounds stay as
  set by the owner and are changed only through a roadmap or ADR edit.
- The default path breaks for a non-editable install. The error names the expected path and the `path=` argument.

## Deviations

- Step 1 findings (GDAL 3.13.3, pyogrio 0.13.0, geopandas 1.2.0): bare geometry and bare Feature are read as one row in
  EPSG:4326; a legacy `crs` member (EPSG:32644) is honoured (`gdf.crs` = EPSG:32644); an empty FeatureCollection reads
  as 0 rows; a 0-byte file raises `DataSourceError` ("not recognized as being in a supported file format"), wrapped
  as `AOIError`. EPSG:5235 area of use confirmed (79.64, 5.86, 81.95, 9.88). k0 = 0.9996 and the 81°E
  central meridian are confirmed by `pyproj.CRS("EPSG:32644").to_json_dict()["conversion"]["parameters"]` (the
  PROJ4-style dict omits them; corrected after science review).
- Surprise: GDAL labels GeoJSON with Z coordinates as EPSG:4979 (3-D). The CRS check therefore compares the datum
  and requires a geographic CRS instead of `crs.equals("EPSG:4326")`, otherwise valid 3-D files were rejected.
- Order of checks: the area is computed after orientation normalisation (needs only a valid polygon); no behavioural
  change.
