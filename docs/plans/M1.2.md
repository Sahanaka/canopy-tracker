# Plan — M1.2 Sentinel-2 seasonal composites + indices

## Goal

Build per-pixel median composites for each Met Department season and season-year from the deduplicated, offset-corrected
and SCL-masked Sentinel-2 L2A record. Derive NDVI, EVI, NDMI and NBR, flag thin pixels, and write 10 m COGs to `outputs/M1.2/`.

Acceptance criteria (docs/ROADMAP.md):
- Baseline-04.00 offset handled; SCL mask; median composites per window from the M1.1 ADR.
- NDVI, EVI, NDMI, NBR per composite; GeoTIFFs (EPSG:32644, 10 m) in `outputs/M1.2/`.
- Unit tests for offset correction, masking and each index on synthetic arrays.

Owner constraints (ADR 0011): use all four windows: FIM Mar–Apr, SWM May–Sep, SIM Oct–Nov and NEM Dec–Feb (December counts
toward the next year). Season-years are 2016–2026, excluding SIM 2026 (partial), so 43 composites. Thin season-years must be
flagged in the outputs.

## Data (checked 2026-11-02)

- **PC `sentinel-2-l2a`**, the frozen M1.1 search `outputs/M1.1/cache/items_s2_2015-06-01_2026-11-02.json` (762 items, 699
  after `dedupe_s2`, all on tile 44NMN; ADR 0010). Asset keys and grids were read from that file:
  - 10 m (`gsd` 10, `proj:shape` 10980²): `B02` blue, `B03` green, `B04` red, `B08` nir.
  - 20 m (5490²): `B8A` (eo `common_name` "rededge", 0.865 µm), `B11` swir16, `B12` swir22, `SCL`.
  - All grids have origin x 399960, y 800040, so the 10 m and 20 m grids nest exactly.
- **No scale or offset metadata on PC items.** The cached items have no `raster:bands`, `scale` or `offset` fields (grep
  over all 762 items). The extensions are eo, sat and projection only. odc-stac therefore has nothing to apply. Its
  scale/offset support is an open enhancement (https://github.com/opendatacube/odc-stac/issues/55), and Step 1 checks this
  by experiment. Assets are raw uint16 DN.
- **Offset.** PC does not harmonise: "propagates to the L2A data hosted by the Planetary Computer"
  (https://github.com/microsoft/PlanetaryComputerExamples/blob/main/datasets/sentinel-2-l2a/baseline-change.ipynb). It
  detects the change through `s2:processing_baseline`. ESA's L2A `BOA_ADD_OFFSET` is −1000, fixed and the same for all
  bands, applied as reflectance = (DN + BOA_ADD_OFFSET) / QUANTIFICATION_VALUE. ESA says to keep negative values, but flag
  them (https://forum.step.esa.int/t/info-introduction-of-additional-radiometric-offset-in-pb04-00-products/35431).
  - CLAUDE.md fixes QUANTIFICATION_VALUE at 10000 and DN 0 as no-data.
  - The PC notebook clips at 1000. We do **not** clip, because CLAUDE.md says to keep small negative values.
  - We decide by baseline only. Baselines found in the archive are 02.12 to 05.13; 05.xx items cover 2016–2021
    (ADR 0010 table).
- **Per-scene metadata:** `s2:mean_solar_azimuth`, `s2:mean_solar_zenith` (elevation = 90 − zenith) and
  `s2:processing_baseline` (string, parsed with `stac.parse_baseline`).
- **Grid.** EPSG:32644 at 10 m. The AOI bbox is snapped outward to the `B02` grid, about 1002 × 1002 px. The 250 000
  inside pixels at 20 m become about 1.0 Mpx at 10 m.

## Design

`stac.py`
- Generalise `aoi_geobox(aoi, items, sensor, asset=None, resolution=None)`. The defaults stay as in M1.1. M1.2 calls it
  with `asset="B02", resolution=10.0`.
- Add `S2_BANDS = {"blue": "B02", "green": "B03", "red": "B04", "nir": "B08", "nir08": "B8A", "swir16": "B11",
  "swir22": "B12"}` as the internal-to-PC name map. The Earth Search mapping is not needed in M1.2.
- Add `load_s2_acquisition(items, geobox, bands) -> xr.Dataset`:
  - Signs just before reading and uses `groupby="solar_day"` and `fail_on_error=True`.
  - Sets `stac_cfg` dtype to uint16 and nodata to 0. 10 m bands use `resampling="nearest"` (identity read), 20 m reflectance
    bands use bilinear and `SCL` uses nearest, through odc-stac's per-band `resampling={...}`.
  - Raises if the items of one group differ in baseline (`mixed_baseline` was 0 in M1.1).
  - Lazy, with `chunks={"x": 512, "y": 512}`.

`masking.py`
- Add `s2_dn_to_reflectance(dn: uint16 array, baseline: str) -> float32`. It casts to float32 **before** subtracting, so
  NumPy 2 / NEP 50 cannot wrap in uint16. It sets DN 0 to NaN and applies `(DN − 1000) / 10000` iff the baseline is ≥ (4, 0),
  else `DN / 10000`. Output is 0–1 with small negative values kept and NaN where DN was 0.
- Reuse `scl_clear(scl, keep_cast_shadow, keep_unclassified)`. Add `SCL_KEEP_M12` from ADR D1.

`indices.py`: pure functions, float32, NaN where any input is NaN, and NaN where the denominator is exactly 0 (D6).
- `ndvi(red, nir)` uses B08.
- `evi(blue, red, nir)` uses 2.5·(NIR−Red)/(NIR + 6·Red − 7.5·Blue + 1) with B08.
- `ndmi(nir08, swir16)` and `nbr(nir08, swir22)` use B8A.
- `all_indices(ds) -> Dataset`. The usual ranges are −1 to 1 for NDVI/NDMI/NBR and about −1 to 1 for EVI, but no
  clipping is applied.

`composites.py`
- `SEASONS = {"FIM": (3, 4), "SWM": (5, 6, 7, 8, 9), "SIM": (10, 11), "NEM": (12, 1, 2)}`. These move out of notebook 01,
  which is not edited. Season-years come from `inventory.season_year`.
- `window_groups(items, season, sy) -> dict[acq_id, list[Item]]`.
- `scene_stack(groups, geobox, keep) -> Dataset[time,y,x]` returns lazy reflectance (float32), indices and a clear mask.
  It also records the per-scene shares removed by each SCL class (2 and 7 logged separately).
- `median_composite(stack) -> Dataset` returns:
  - median reflectance per band,
  - median of per-scene indices (D2),
  - `n_obs` (uint16),
  - `doy_median` (median day-of-year of the clear observations, uint16, 0 = none),
  - `thin` (uint8: 0 none, 1 if n_obs ∈ {1, 2}, 2 if ≥ 3; D3).
- `composite_window(items, aoi, season, sy, out_dir, keep) -> Path`. It is resumable: it skips a window-year whose outputs
  carry the same item-ids hash and parameters in their tags.

`io.py`: `write_cog(da, path, nodata, descriptions, tags)` writes a GDAL COG driver file with deflate (predictor 3 for
float, 2 for int).

Notebook `notebooks/02_s2_composites.ipynb`, kept thin:
1. Load the AOI and the frozen items, then dedupe.
2. Table of the 43 window-years (scenes, baselines, sun angles).
3. Pilot one thin and one full window-year (SIM 2023, SWM 2023) and record peak memory and timings.
4. Full loop.
5. Summary table (zero-obs, ≤ 2-obs and thin shares) checked against ADR 0011.
6. Maps: NDVI/NBR and `n_obs` for a few windows, SCL 2/7 removal per scene, and how each composite's index
   distribution compares with the scene-level ones.

Outputs in `outputs/M1.2/`, git-ignored, rendered as `s2_<sy>_<WIN>_*.tif`:
- `_indices.tif`: 4 bands, float32, NaN nodata, band descriptions.
- `_reflectance.tif`: 7 bands, float32, NaN.
- `_obs.tif`: uint16 bands `n_obs`, `thin` and `doy_median`, nodata 65535 outside the AOI.
- `clear_masks/s2_<sy>_<WIN>.npz`: bit-packed per-scene 10 m clear masks plus acq_ids, for the M1.3 shadow share.
- `scenes_used.csv`: acq_id, item ids, baseline, sun az/elev, window, sy, `scl_share_2` and `_7`, clear fraction.
- `composite_summary.csv`.
- `README.md` with the resolved env (`environment.explicit.txt`, plus the rasterio/GDAL/PROJ/odc versions).

Size estimate:
- Per window-year uncompressed: indices 16 MB, reflectance 28 MB, obs 6 MB, masks about 4 MB.
- Over 43 window-years this is about 2.3 GB raw. Deflate should bring it to roughly 1–1.5 GB; the pilot measures it.

No new packages: rasterio's COG driver and rioxarray are already pinned (ADR 0004).

## Science checks

- **Offset.** The decision uses the baseline only, never the date. We cast to float32 before subtracting, DN 0 becomes
  NaN, and negative values are kept. Applying the offset twice is ruled out: PC has no `raster:bands` and Step 1 compares
  odc-stac DN with a direct rasterio read. Bilinear resampling acts on DN; because the offset is affine and constant, it
  commutes with resampling. Nodata 0 is declared so the warp excludes it.
- **Duplicates.** `dedupe_s2` runs before any grouping. Platforms 2A, 2B and 2C are all used.
- **SCL.** The keep-set follows D1, and classes 2 and 7 stay configurable. The share each removes is logged per scene and
  per composite. SCL is read at 20 m and resampled to 10 m with nearest only.
- **Indices and bands.** B08 for NDVI/EVI and B8A for NDMI/NBR. 20 m reflectance goes bilinear to 10 m. NDMI is the
  moisture index, not the green/NIR NDWI.
- **Clouds.** Windows come from ADR 0011. Thin pixels and season-years are flagged from the data, and the list is checked
  against ADR 0011: SIM in most years, FIM/NEM 2016, FIM 2017. SCL misses some cloud edges (2024-10-23 evidence), so see D3.
- **Terrain.** The shadow flag is deferred to M1.3 (D4), which needs the DEM. M1.2 stores per-scene sun geometry and
  per-scene clear masks so M1.3 can compute the shadow share per composite. The README says the composites are not yet
  terrain-flagged.
- **Land cover.** Not applied: composites are input layers, and masking happens in M1.4/M1.6.
- **CRS.** EPSG:32644, 10 m, AOI loaded from the file only. Pixels outside the AOI are nodata.

## Tests (no network; `tests/test_indices.py`, `test_composites.py`, plus `test_masking.py`/`test_stac.py`)

- **Offset:**
  - DN [0, 1, 999, 1000, 1500, 65535] with baselines "03.00", "04.00" and "05.10".
  - Pre-04.00 gives DN/1e4. ≥ 04.00 gives (DN−1000)/1e4, so 999 → −0.0001 (kept, not wrapped). DN 0 gives NaN.
  - Output dtype is float32. "04.00" vs "4.0" parsing is checked.
- **SCL:** the keep-set mask across all 12 classes for each D1 option, and the share-logging sums.
- **Indices:** each formula on hand-computed values. Examples: NDVI(0.05, 0.45) = 0.8; EVI with blue = 0.02 gives
  2.5·0.4/(0.45+0.3−0.15+1) = 0.625; NDMI/NBR use the B8A argument. NaN propagates, a zero denominator gives NaN, and the
  dtype is float32.
- **Median:**
  - A stack with NaNs, n = 0/1/2/3/odd/even, gives the expected `n_obs`, `thin` and median.
  - A one-scene outlier among 3 is rejected but not among 2.
  - Median-of-indices differs from index-of-medians on a constructed case, which documents D2.
- **Windows:** NEM 2016 takes Dec 2015 to Feb 2016; SIM 2026 is excluded as partial.
- **Output:** `write_cog` round-trip (CRS, transform, nodata, descriptions, dtype) to tmp_path. Resume skips a window-year
  when the tags match and recomputes when the item hash changes.
- **`@pytest.mark.network`:** one recent ≥ 05.00 acquisition and one 02.12 acquisition over the AOI (skipped if the AOI
  is absent). It checks that the odc-stac DN equals a direct rasterio window read, that the output is float32 on a 10 m
  EPSG:32644 grid, and that reflectance equals the formula exactly.

## Decisions needed

- **D1 SCL keep-set (ADR 0012).** Evidence from ADR 0010: class 2 removes 0.11 % of pixels on average (0.21 % before
  04.00, 0.03 % after), class 7 removes 1.70 % (p90 5.8 %); neither has been validated. (a) Mask both (`clear_base`,
  matches the ADR 0011 tables). (b) Keep 2, mask 7. (c) Keep both. **Recommend (b).** Class 2 is cast shadow on real
  surfaces (dark soil/burn before 04.00): masking it would bias against shaded slopes, which M1.3 flags explicitly, and it
  costs almost nothing either way. Class 7 is "undecided", and SCL already leaks cloud edges, so masking it is the cautious
  choice at a cost of about 1.7 percentage points of observations. Thin flags are computed with the chosen set.
- **D2 Composite statistic (ADR 0013).** (a) Per-band median, then indices from the composite. (b) Median of per-scene
  indices. (c) Geomedian (Roberts et al. 2017, doi:10.1109/TGRS.2017.2723896; needs a new package). A per-band median
  builds a spectrum that no date observed (Flood 2013, doi:10.3390/rs5126481), so (a) and (b) differ. **Recommend (b) for
  the indices** (each value is an observed index, and this matches M1.5's "annual median NBR"), **plus a per-band median
  reflectance kept for display only** (M1.8 true-colour).
- **D3 Thin flag and extra cloud screening (in ADR 0013).** A median rejects one contaminated value only when n ≥ 3, so
  the flag is `thin` if n_obs ≤ 2 (a logical bound, not a tuned number). **Recommend no extra screening in M1.2** (no
  temporal-outlier or spectral rule, no SCL buffer). Every such rule needs a k, buffer or threshold that this data cannot
  ground. Report the share of thin pixels per window-year and revisit if field checks show cloud leakage.
- **D4 Terrain flag (ADR 0014).** (a) Defer to M1.3 and store per-scene sun geometry plus per-scene 10 m clear masks
  (about 4 MB per window-year). (b) Block M1.2 on M1.3. **Recommend (a).** M1.3 then reports composites with and without
  the flag.
- **D5 Output layout (in ADR 0013 or README).** (a) Per window-year files: indices, reflectance and obs, with 7
  reflectance bands including B03 for true colour. (b) One time-stacked file per index (43 bands). (c) Indices only, no
  reflectance. **Recommend (a)** at about 1–1.5 GB. Reflectance is needed for the M1.8 drape, and B03 is added only for
  that.
- **D6 Index guard.** NaN only where the denominator is exactly 0. No clipping. Report the share of values outside
  [−1, 1] per composite. **Recommend.**
- **D7 Item source.** (a) Reuse the frozen M1.1 search (the same scenes as the ADR 0011 tables). (b) A fresh search.
  **Recommend (a).** The README records the item-list hash.

## Risks

- **Time.** M1.1 read SCL only (1481 reads in 915 s). M1.2 reads 8 assets × 699 acquisitions with about 4× the pixels
  for the 10 m bands. A cold run is estimated at 1.5–4 h; the pilot measures it. Each window-year is resumable.
- **Memory.** The largest window (SWM, up to 39 scenes) with 8 bands × 39 × 1 Mpx × 4 B is about 1.2 GB if held at once.
  Splitting into 512² spatial chunks with time = −1 brings it to about 330 MB per chunk. Use the threaded scheduler with
  2–4 workers. The pilot records peak RSS, and the chunk size is lowered if it runs over.
- **Cloud leakage.** With n ≤ 2, residual SCL misses pass straight through. SIM composites are the least reliable. The
  thin flag must accompany every use.
- **Mixed baselines inside a window.** Pre-04.00 and post-04.00 eras sit in different years. The offset handles the level
  shift, but the SCL behaviour changed at 04.00 (ADR 0010), and this can look like change.
- **Phenology.** SWM spans 5 months, so per-pixel `doy_median` must be checked before comparing years.
- **Negative reflectance.** In dark or shadowed pixels it can push the normalised indices outside [−1, 1] or blow up
  EVI. The values are kept and reported (D6).
- **SAS expiry.** Sign per acquisition group just before reading.

## Deviations

Recorded during implementation (2026-11-02). None changes an owner-approved decision D1-D7.

1. **`write_cog` signature.** It takes a NumPy array plus `transform` and `crs` (`write_cog(array, path, transform, crs, nodata,
   descriptions, tags)`) instead of a DataArray, so it does not depend on rioxarray's CRS bookkeeping. It writes a temporary
   GTiff and copies it with the GDAL COG driver (the COG driver cannot be written to directly).
2. **`doy_median` is `window_day_median`.** NEM spans the new year (Dec-Feb), so a median day-of-year of 350 and 20 is
   meaningless. The band is the median day of the window (1 = first day of the window, e.g. 1 December for NEM) of the valid
   observations, uint16, 0 = none. Same band position in `_obs.tif`.
3. **Valid observation = SCL clear AND all seven reflectance bands non-zero.** The plan masked by SCL only. The extra condition
   keeps DN 0 (no-data) out of the medians. It also covers the one case found where it matters: acquisition
   `sentinel-2a_2023-07-06` is kept by `dedupe_s2` as the 05.10 reprocessed item, whose B04 is 98 % DN 0 and SCL 84 % class 1
   in the AOI, while the dropped 05.09 item has 84 % valid data. The scene contributes no observations. This is a limitation of
   the CLAUDE.md "keep the highest baseline" rule (1 of 699 kept scenes has SCL class 1 over 50 %), not changed here.
4. **Geobox size.** The AOI snapped to the `B02` grid is 1001 x 1001 px (plan: about 1002 x 1002).
5. **Extra helpers beyond the plan.** `composites.season_years`, `items_hash`, `is_done`, `unpack_clear_masks`,
   `collect_summaries`, `indices.normalized_difference` and `indices.out_of_range_share`. Per window-year the composite writes
   a `meta/s2_<sy>_<WIN>.json` sidecar (resume key plus the summary and scene rows); `composite_summary.csv` and
   `scenes_used.csv` are assembled from the sidecars by the notebook.
6. **Thin season-year flag is data-derived.** `thin_season_year` is True where the median `n_obs` over the AOI is <= 2 (the
   same bound as the pixel flag, D3). The ADR 0011 list is compared against it in the notebook, not copied into code.
7. **`composite_summary.csv` column `n_scenes_with_clear`** (scenes with clear fraction > 0) replaces `n_scenes_with_data`:
   for SCL files that declare no nodata GDAL writes class 0 as 1, so class-0 share cannot identify empty scenes.
8. **ruff.** `E501` is ignored for `notebooks/*` (long README text in a notebook cell); source and tests keep the 100-column limit.
9. **Order of steps 7 and 8.** The ADRs cite numbers from the full run, so the full run (with a script calling the same
   `composite_window` loop) came before the ADR commit; the notebook, which resumes from those outputs, was committed last.
10. **Output size.** Measured about 40 MB per window-year (indices 14 MB, reflectance 25 MB, obs 0.3 MB, masks < 0.1 MB), so
    about 1.7 GB for 43, above the plan's 1-1.5 GB estimate. Peak memory and timings are in ADR 0013 and the README.
11. **SCL nodata handling.** For SCL files that declare no nodata, GDAL warns "Value 0 ... changed to 1" and class 0 reads as 1
    (checked on 2026-09-08). Both are masked, so masks are unaffected; the stored `scl_share_0` is understated for those
    scenes. B04 DN 0 and the 20 m bands' 0 were checked on the same scene: valid pixels show no edge contamination.
