# Plan — M1.1 Data availability audit

## Goal

Build an inventory of every Sentinel-2 L2A and Landsat C2 L2 acquisition over the AOI, with the share of AOI pixels that
are clear on each one. Use it to propose composite windows for M1.2 and the first year of the Landsat record for M1.5.

Acceptance criteria (docs/ROADMAP.md):
- STAC search over the AOI for `sentinel-2-l2a` (full archive, mid-2015→now) and `landsat-c2-l2` (full archive, 1982→now).
- Deduplicate reprocessed Sentinel-2 items (same datetime + MGRS tile, keep the highest baseline); report counts by
  platform and baseline.
- Per scene: share of AOI pixels clear after masking (SCL / QA_PIXEL), not just scene-level cloud %.
- Report the share of AOI pixels removed by SCL class 2 (cast shadow) and class 7 (unclassified) separately.
- Plots: clear-pixel % by month × year for each sensor. Writes `outputs/M1.1/scene_inventory.parquet`.
- ADR proposing composite windows (seasons) based on the plot, and the first year the Landsat record supports for M1.5.

**Blocked on the AOI:** `data/aoi/aoi.geojson` does not exist yet. Package code and unit tests (Steps 1–6) don't need
it. The notebook run, outputs, both ADR proposals and the roadmap tick (Steps 7–9) do. See D1.

## Data (sources checked 2026-11-01)

- **S2:** PC `sentinel-2-l2a`, archive from 2015-06-27, open-ended.
  https://planetarycomputer.microsoft.com/api/stac/v1/collections/sentinel-2-l2a
  - Asset `SCL`: 20 m, `proj:shape` 5490², no `raster:bands`, so nodata is not declared.
  - Item properties seen on a live item: `platform` ("Sentinel-2A"), `s2:processing_baseline` (string, "05.10"),
    `s2:mgrs_tile`, `sat:relative_orbit`, `eo:cloud_cover`, `s2:mean_solar_azimuth`, `s2:mean_solar_zenith`,
    `s2:nodata_pixel_percentage`, `proj:epsg` 32644.
  - Duplicates confirmed: item ids `S2A_MSIL2A_20230328T050601_R076_T44NNN_20240805T215617` (05.10) and `..._20230328T085642`
    (05.09) have the same `datetime`. The last id field is the processing time.
  - A point near the AOI belt returned tile 44NNN, and the main session saw 44NMN. 44NMN and 44NNN overlap at
    eastings 499 980–509 760 m, so the AOI can lie on both. Tiles are found from the search and never hard-coded.
  - SCL classes are as listed in CLAUDE.md. PSD 15.0 / PB 05.11 renamed class 2 from DARK_FEATURES to CAST_SHADOW,
    and its computation has been unchanged since PB 04.00. Before 04.00, class 2 also held dark soils and burn scars,
    which later moved to class 7.
    https://dataspace.copernicus.eu/news/2024-7-18-sentinel-2-product-specification-document-psd-version-150
- **Landsat:** PC `landsat-c2-l2`, 1982-08-22→now, platforms `landsat-4/5/7/8/9`.
  https://planetarycomputer.microsoft.com/api/stac/v1/collections/landsat-c2-l2
  - Live item `LE07_L2SP_141055_20001208_02_T1` has these properties: `landsat:wrs_path` "141", `landsat:wrs_row` "055",
    `landsat:collection_category` (T1/T2), `landsat:correction` (L2SP/L2SR), `view:sun_azimuth`, `view:sun_elevation`,
    `eo:cloud_cover`, `landsat:cloud_cover_land`, `proj:epsg` 32644. Its 30 m grid origin is offset by 15 m from multiples of 30.
  - Asset `qa_pixel`: uint16, nodata 1, 30 m, with a `classification:bitfields` list.
  - QA_PIXEL for L4–7 (USGS LSDS-1618 v4.0, Table 5-5):
    https://d9-wret.s3.us-west-2.amazonaws.com/assets/palladium/production/s3fs-public/media/files/LSDS-1618_Landsat-4-7_C2-L2-ScienceProductGuide-v4.pdf
    - Bits: 0 fill, 1 dilated cloud, **2 unused**, 3 cloud, 4 cloud shadow, 5 snow, 6 clear, 7 water,
      8–9 / 10–11 / 12–13 confidences, **14–15 unused**.
    - §5.2.1 item 4: the L4–7 clear bit (6) is wrong in some cases, so don't use bit 6.
  - QA_PIXEL for L8–9: the same layout, except **bit 2 is cirrus** and **bits 14–15 are cirrus confidence**.
    https://www.usgs.gov/landsat-missions/landsat-collection-2-quality-assessment-bands (guide LSDS-1619 v6:
    https://d9-wret.s3.us-west-2.amazonaws.com/assets/palladium/production/s3fs-public/media/files/LSDS-1619_Landsat8-9-Collection2-Level2-Science-Product-Guide-v6.pdf)
  - L7 SLC-off after 2003-05-31. The gaps appear as fill.
- **APIs at the env pins:**
  - pystac-client 0.9.0: `Client.open(url)` and `search(collections, intersects, datetime, limit)`; `.items()`
    paginates through `next` tokens.
  - planetary-computer 1.0.0: `planetary_computer.sign(item)`.
  - odc-stac 0.5.3 / odc-geo 0.5.3: `odc.stac.load(items, bands, geobox|crs+resolution+geopolygon, groupby, resampling,
    nodata, dtype, fail_on_error, chunks)`.
  - Step 1 checks every signature with `inspect.signature`; nothing is assumed.
- Sri Lanka local date: `Asia/Colombo` (UTC+05:30). Overpasses are about 05:06 UTC, so the UTC and local dates match. The column is computed anyway.

## Design

`src/highland/stac.py`
- `PC_STAC_URL`.
- `search_items(collection: str, aoi: GeoDataFrame, start: str, end: str, client=None) -> list[pystac.Item]`:
  returns all pages, unsigned.
- `save_items(items, path)` / `load_items(path)`: cache an ItemCollection as JSON, so reruns skip the search.
- `parse_baseline(s: str) -> tuple[int, int]`: parses "05.10" to (5, 10). Never parse it as a float.
- `s2_processing_time(item) -> str`: last id field, `YYYYMMDDTHHMMSS`.
- `dedupe_s2(items) -> tuple[list[Item], DataFrame]`: groups on (`datetime`, `s2:mgrs_tile`) and keeps the highest
  baseline. Ties go to the latest processing time. Also returns a table of dropped items and the reason. It logs (doesn't
  merge) any same-day items on the same tile, orbit and platform whose datetimes differ.
- `acquisition_groups(items, sensor) -> dict[str, list[Item]]`: key is (platform, local solar day). This merges
  overlapping MGRS tiles and WRS rows of one pass (D3).
- `aoi_geobox(aoi, items, resolution) -> GeoBox`: EPSG:32644 grid snapped to the items' native pixel grid (20 m S2,
  30 m Landsat), cropped to the AOI bbox, so reading needs no resampling.

`src/highland/masking.py` (works on numpy/xarray, pure, no I/O)
- `SCL_CLASSES: dict[int, str]` (0–11), `SCL_KEEP_BASE = {4, 5, 6}`.
- `scl_class_shares(scl: ndarray, inside: ndarray[bool]) -> dict[int, float]`: share 0–1 of the AOI pixels in each
  class. Out-of-footprint pixels load as 0 (no-data).
- `scl_clear(scl, keep_cast_shadow: bool, keep_unclassified: bool) -> ndarray[bool]`.
- `QA_BITS_L47 = {fill:0, dilated:1, cloud:3, shadow:4, snow:5}`, `QA_BITS_L89 = {... , cirrus:2}`.
- `qa_flags(qa: ndarray[uint16], platform: str) -> dict[str, ndarray[bool]]`. Bit 2 is read only for landsat-8/9.
  Bit 6 is never used.
- `qa_clear(qa, platform, mask_cirrus: bool = True) -> ndarray[bool]`: clear means none of bits 0, 1, 3, 4, 5 are set,
  and also bit 2 unless `mask_cirrus=False` (L8/9 only).

`src/highland/inventory.py` (new; D10)
- `audit_acquisition(items, sensor, geobox, inside) -> dict`: one `odc.stac.load` of `SCL` (nodata=0, uint8) or
  `qa_pixel` (nodata=1, uint16) at the native resolution with `fail_on_error=True`. The asset is signed just before it
  is read. Returns the row fields and per-pixel clear booleans.
- `run_audit(sensor, items, aoi, out_dir, resume=True) -> DataFrame`: loops over groups and appends each row to
  `out_dir/cache/<sensor>_rows.parquet` in batches. It skips groups already done and retries 3× with backoff. A group
  that still fails gets a row with `status="error"` and its message, so it is never dropped silently. Memory: one
  acquisition at a time (about 500×500 px).
- Per-pixel counters (D8): for each (year, month), uint16 counts of clear observations (S2: base keep-set, class 2 and
  class 7 counted separately; Landsat: clear with and without cirrus).
- `month_year_table(df, value) -> DataFrame` and `window_summary(df, counts, windows) -> DataFrame`.

**Inventory schema** (`scene_inventory.parquet`, one row per acquisition)
- Identity and time: `sensor`, `platform`, `acq_id`, `datetime_utc`, `date_local`, `year`, `month`.
- Source items: `item_ids` (list), `tiles` (MGRS tiles or path/row list), `baselines` (list, S2), `baseline_max`,
  `collection_category`, `correction`, `relative_orbit`.
- Scene-level metadata: `eo_cloud_cover_mean`.
- Sun geometry: `sun_azimuth_deg`, `sun_elevation_deg` (S2 uses 90 − zenith; the mean over the items).
- Pixel shares, each 0–1 of the AOI pixels: `aoi_pixels`, `valid_frac`, `scl_share_0` … `scl_share_11` (S2);
  `qa_fill/dilated/cloud/shadow/snow/cirrus_share` (Landsat).
- Clear fractions: S2 `clear_base` (keep 4/5/6), `clear_keep2`, `clear_keep7`, `clear_keep27`; Landsat `clear`,
  `clear_nocirrus`.
- Flags and run status: `slc_off`, `status`.
- SCL classes are mutually exclusive, so any keep-set can be recomputed later from the 12 share columns.

**Notebook** `notebooks/01_availability.ipynb` (thin):
1. Load the AOI. Search, cache and dedupe.
2. Tables: items and acquisitions by platform × baseline (S2) and by platform × category (Landsat); the tiles and
   path/rows found, with AOI coverage.
3. `run_audit` for both sensors.
4. Heatmaps of month × year per sensor:
   - the summed clear fraction, i.e. the expected clear observations per AOI pixel;
   - the number of acquisitions;
   - for S2, the base keep-set and the variant that keeps classes 2 and 7.
5. Class 2 and class 7 shares over time, coloured by baseline < 04.00 vs ≥ 04.00.
6. Window tables (D7).
7. Landsat per-year table: share of AOI pixels with ≥ 1 clear observation and the median per-pixel count.

**Outputs** in `outputs/M1.1/`:
- `scene_inventory.parquet`, `dedupe_dropped.csv`, `clear_counts_{s2,landsat}.tif` (bands = year-month, with
  descriptions).
- PNG plots.
- `README.md` with the resolved env (`micromamba env export --explicit` saved alongside, per outputs/README.md).
- `cache/` (git-ignored).

## Science checks

- **Offset:** not applicable. SCL and QA_PIXEL are categorical, and no reflectance is read. The baseline is still
  parsed and recorded per item.
- **Duplicates:** deduplicate per (datetime, tile) before any count. Counts are reported before and after.
  Sentinel-2C appears as its own platform.
- **SCL:** classes 2 and 7 are reported separately and with all four keep variants. Before 04.00, class 2 means
  "dark features", so the class 2 share is split by baseline. SCL is read at its native 20 m grid with no resampling;
  nearest-neighbour upsampling to 10 m would leave the shares unchanged.
- **Landsat:**
  - Masking uses bits 0, 1, 3, 4, 5. Cirrus (bit 2) is used for L8/9 only and reported both ways. Bit 6 is never used.
  - SLC-off gaps are fill: they lower `valid_frac` and count as not clear, which is correct for availability.
  - No harmonisation is needed, because no reflectance is read.
- **Clouds/seasons:** windows come from this data (D7). Nothing about the seasons is assumed in code.
- **CRS:** EPSG:32644 on the native grids. The AOI is loaded only from the file and rasterised for the `inside` mask.
- Terrain and land cover: not applied here. Sun angles are stored for the M1.3 per-scene shadow flag.

## Tests (`tests/test_stac.py`, `test_masking.py`, `test_inventory.py`; no network)

- `parse_baseline` ordering: "05.09" < "05.10" and "04.00" < "05.00".
- `dedupe_s2` uses synthetic `pystac.Item`s:
  - same datetime and tile → the highest baseline is kept;
  - an equal baseline → the latest processing time is kept;
  - different tiles on the same datetime → both are kept;
  - the dropped table is correct.
- `acquisition_groups` merges two tiles of one pass and keeps different platforms apart.
- `scl_class_shares` on a hand-built array: the shares sum to 1, and the outside-AOI pixels are ignored.
- `scl_clear` covers each of the four variants.
- `qa_flags`/`qa_clear` use bit patterns built from the cited tables, including LSDS-1618 Table 5-6 example values
  1, 5440, 5442, 5896, 7440, 13664:
  - for L4–7, bit 2 is ignored;
  - for L8/9, cirrus is masked or not according to the toggle;
  - bit 6 has no effect.
- `aoi_geobox` snaps to a synthetic transform with a 15 m offset.
- `run_audit` with a monkeypatched loader:
  - resume skips groups already done;
  - a failure gives an error row;
  - the parquet round-trips.
- `month_year_table` sums correctly.
- `@pytest.mark.network`: search 1 month of each collection and audit one acquisition. The test loads the real AOI
  and **skips if the AOI is absent**, because it never hard-codes coordinates.

## Decisions needed

- **D1 AOI blocker / PR split.** (a) PR 1 now: package code and tests, with M1.1 left unticked. PR 2 after the AOI
  lands: the notebook, the run, outputs README, ADRs and the tick. (b) One draft PR held until the AOI exists.
  **Recommend (a)**, as in M0.3. The notebook goes in PR 2 because the verifier must execute it.
- **D2 Read resolution.** (a) Native (SCL 20 m, QA 30 m) over the AOI bbox. (b) COG overviews. **Recommend (a)**: the
  resampling used to build the overviews is not documented, and averaging would corrupt class codes. The AOI is small
  (about 0.25 Mpx per S2 read).
- **D3 Row unit.** (a) One row per acquisition (platform + local day), merging overlapping tiles and rows and listing
  the item ids. (b) One row per deduplicated item. **Recommend (a)**: with (b), tile overlap double-counts the same
  pixels. The item-level table stays in `cache/`.
- **D4 Clear definitions.** S2: store all 12 class shares plus four variants (classes 2 and 7 kept or masked);
  M1.2's ADR chooses among them. Landsat: mask bits 0, 1, 3, 4, 5, plus cirrus on L8/9 (reported both ways).
  **Recommend as stated.**
- **D5 Landsat tiers.** (a) Include T1 and T2 and report them separately. (b) T1 only. **Recommend (a)** for the
  audit, since T2 is common in cloudy tropics. M1.5 decides which tiers to use.
- **D6 Plot metric.** (a) Summed clear fraction per month-year, which equals the expected clear observations per
  pixel and needs no threshold, plus the acquisition count. (b) The count of scenes with clear ≥ X %. **Recommend (a)**:
  (b) would need an invented X.
- **D7 Windows and first Landsat year.**
  - Candidate windows are the four Met Dept seasons (from CLAUDE.md). December is assigned to the following year's NE
    monsoon.
  - For each window × year: the share of AOI pixels with zero clear observations, and the median per-pixel count.
  - For Landsat: the per-year share of pixels with ≥ 1 clear observation. One observation is the logical minimum for
    a composite, not a tuned number.
  - **Recommend:** the ADR presents these tables and proposes windows and a first year. The owner accepts or changes
    them, and the rule used is written in the ADR as an assumption. No percentage cut-off is set in code.
- **D8 Per-pixel count rasters.** (a) Write `clear_counts_*.tif` (about 30–60 MB at most). (b) AOI fractions only.
  **Recommend (a)**: D7's zero-observation shares need per-pixel counts.
- **D9 pyarrow.** It is not in `environment.yml`, and parquet needs it. Add `pyarrow==<resolved version>` with an exact
  pin, after the four-platform dry-run solve (ADR 0004). **Recommend.**
- **D10 New module `highland/inventory.py`.** It is not in CLAUDE.md's layout. **Recommend** adding it. The owner
  updates the CLAUDE.md layout, because agents don't edit CLAUDE.md.

## Risks

- **Volume and time are estimates, to be measured in Step 7's one-year pilot:**
  - S2: roughly 70 acquisitions/yr × 11 yr (×2 tiles, plus duplicates) gives about 1–2.5 k items.
  - Landsat: 1–2 path/rows × 23 passes per sensor per year; the 1980s–90s are likely sparse.
  - At about 1–3 s per read, a full run takes about 1–3 h. The resume cache bounds the cost of a rerun.
- SAS tokens expire, so each group is signed just before its read. PC throttling is handled by backoff.
- `fail_on_error=False` would turn failed reads into fill without notice, so it is never used.
- Tiles or path/rows in a different UTM zone would force resampling. This is logged and done with nearest.
- `eo:cloud_cover` is tile-wide and misleads over a 10 km AOI. It is stored only for comparison.
- SCL's own errors (for example, cloud read as class 2 or 7 on shaded slopes) make "clear" optimistic or pessimistic.
  The 2/7 variants show the size of this effect; nothing here validates it.
- Older S2 baselines (< 04.00) and any Microsoft-processed early L2A may have different SCL behaviour. Counts by
  baseline expose this.
- ADR numbers: use the next free number after M0.4's ADR (check at write time).
