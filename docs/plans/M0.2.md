# Plan — M0.2 CI

## Goal

Run lint and offline tests on GitHub Actions for every PR and every push to the integration branch, from the
pinned conda env, and document a badge and a "How to run" section in the README.

Acceptance criteria (docs/ROADMAP.md):
- GitHub Actions workflow running ruff and `pytest -m "not network"` on push and PR (micromamba or pip).
- README badge and a "How to run" section.

Note: CI runs `-m "not network and not viewer"` (ADR 0005). This deselects more tests than the roadmap
expression, so the criterion is still met.

## Design

`.github/workflows/ci.yml` (rewrite):
- `name: ci`. Triggers:
  - `push: branches: [task/M0.0-kit-setup]`. This seeds the env cache that PRs restore from the base branch, and it
    gives the badge its runs (see D1).
  - `pull_request:` with no branch filter.
  - `workflow_dispatch:` for manual reruns.
  - Pushes to `task/*` branches do not trigger runs, so a PR does not run twice.
- `permissions: contents: read` at the top level.
- `concurrency: group: ${{ github.workflow }}-${{ github.ref }}`, `cancel-in-progress: true`.
- One job, `test`, on `ubuntu-latest`. `timeout-minutes: 20` is a ceiling against hangs, not a measured value.
  The default shell is `bash -el {0}`.
- Steps, with actions SHA-pinned and a version comment (D2):
  1. `actions/checkout@<sha> # v7.0.1` with `persist-credentials: false`.
  2. `mamba-org/setup-micromamba@<sha> # v3.2.1` with `environment-file: environment.yml`, `cache-environment: true`,
     `post-cleanup: none` (ephemeral runner). Pinning the micromamba version is optional (D5).
  3. `pip install -e . --no-deps --no-build-isolation`. This uses the pinned `hatchling==1.33.0` and matches the
     laptop install and ADR 0004 (D4).
  4. Restore the pre-commit hook cache with `actions/cache@<sha>` on `~/.cache/pre-commit`, keyed on the hash of
     `.pre-commit-config.yaml`. The implementer confirms the current actions/cache release and SHA in Step 1.
  5. Lint: `pre-commit run --all-files --show-diff-on-failure`. This replaces the two separate ruff steps (D3).
  6. Tests: `pytest -m "not network and not viewer"`. `-ra` and `--strict-markers` come from pyproject.
  7. Print `micromamba list` for the log, so a CI failure can be tied to resolved versions.
- No Python or OS matrix: ADR 0003 makes 3.13 the only reference env.

`README.md` (rewrite, accurate to what exists now):
- Title, a one-paragraph mission from CLAUDE.md, and the badge
  `[![ci](https://github.com/Sahanaka/canopy-tracker/actions/workflows/ci.yml/badge.svg?branch=task%2FM0.0-kit-setup)](…/actions/workflows/ci.yml)`.
  Step 4 checks whether the `%2F` form or a literal `/` renders correctly.
- "How to run":
  - Create the env with `micromamba create -f environment.yml` (or `conda env create -f environment.yml`), then
    `micromamba activate highland`.
  - Editable install: `pip install -e . --no-deps --no-build-isolation`.
  - `pre-commit install`, then `pre-commit run --all-files`.
  - Offline tests: `pytest -m "not network and not viewer"`. Network tests: `pytest -m network` (none exist yet).
  - Optional 3D/viewer env: `micromamba install -n highland -f environment-3d.yml`, then
    `playwright install chromium`, then `pytest -m viewer` (none exist yet).
- A short layout pointer to CLAUDE.md, docs/ROADMAP.md and docs/decisions/. No notebook instructions yet.
- `docs/decisions/0006-ci-workflow.md` records D1–D5. Tick M0.2 in docs/ROADMAP.md.

## Decisions needed

- **D1 Push trigger and badge branch.** `main` is never merged into.
  - (a) Push on `[task/M0.0-kit-setup]`, with the badge on `?branch=task%2FM0.0-kit-setup`.
  - (b) Option (a), but also keep `main` in the push list for later.
  - (c) The owner changes the GitHub default branch to `task/M0.0-kit-setup`. Then the badge needs no `?branch=`,
    PRs target it by default and task branches can restore its caches. This is a repo-settings change only the owner
    can make.
  - **Recommend (a)+(b): push on `[task/M0.0-kit-setup, main]`**, with an explicit `?branch=` badge. Mention (c) to
    the owner as optional. Revisit the badge if the integration branch is ever renamed or merged into `main`.
- **D2 Action pinning.**
  - (a) Major tags (`@v7`, `@v3`): simple, but tags can move.
  - (b) Full commit SHAs with a `# vX.Y.Z` comment, following GitHub's security guidance.
  - **Recommend (b).** Bumps are manual, or Dependabot `github-actions` in a later task.
- **D3 Lint step.**
  - (a) Separate `ruff check` and `ruff format --check` steps.
  - (b) A single `pre-commit run --all-files --show-diff-on-failure`, which also runs nbstripout, check-yaml, EOF and
    whitespace checks and the large-file check, from the same config as laptops.
  - (c) Both, which duplicates ruff.
  - **Recommend (b).** Ruff still comes from the env's pinned binary (local hooks), so there is one version source.
    The `--fix` and format hooks make pre-commit fail when they modify a file.
- **D4 Editable install flags.**
  - (a) Keep `--no-deps` only, which fetches hatchling from PyPI.
  - (b) Add `--no-build-isolation`, which uses the env's pinned hatchling and matches the README.
  - **Recommend (b).**
- **D5 Cache and micromamba version.**
  - (a) Cache the env (keyed on the env-file hash) with micromamba unpinned (the latest stable release).
  - (b) Option (a), and also pin `micromamba-version`.
  - (c) No cache, which gives a fresh solve every run.
  - **Recommend (a).** Floating transitive deps can make a cached env differ from a fresh solve. The 7-day eviction
    limits that drift, and step 7 logs resolved versions. A weekly uncached scheduled run is possible later.

## Risks

- **Stale cache:** a cached env hides breakage from floating transitive deps until the cache is evicted or
  `environment.yml` changes. Mitigation: `micromamba list` in the log, D5 follow-up.
- **No caches on the first PR:** caches made on task branches are not visible to siblings. Until a push to
  `task/M0.0-kit-setup` seeds the cache, every PR solves cold, which takes a few minutes.
- **Linux only:** CI checks linux-64 only. macOS and Windows rely on the M0.1 dry-run solves (ADR 0003).
- **pre-commit network use:** pre-commit fetches `pre-commit-hooks` from GitHub. A GitHub outage fails lint, not tests.
- **SHA pins age:** Node runtime deprecations can break old pins. Bump with the versions in the comment.
- **Badge query string:** a slash in the branch query may need URL-encoding (checked in Step 4).
- **No actionlint:** workflow syntax errors only show up on push. check-yaml catches YAML errors only.

## Deviations

- Step 4 (push, open PR, confirm the run, check badge rendering) was not done by the implementer; the main session
  pushes and checks the PR run. The badge `%2F` encoding is therefore unchecked.
- actions/cache was pinned to v6.1.0 (`55cc8345863c7cc4c66a329aec7e433d2d1c52a9`), the latest tag per `git ls-remote`.

- `cache-environment` and the pre-commit cache were validated only by syntax (actionlint v1.7.7 and yaml parse);
  no hosted run was possible locally.
