# Plan — M1.3 Terrain

**Status:** approved by the owner on 2026-11-03 with recommendations D1-D9 as written.

## Goal

Derive slope, aspect and hillshade from Copernicus GLO-30. Compute a per-scene terrain-shadow mask from each M1.2 scene's sun
geometry and aggregate it per composite as the share of valid observations in shadow (ADR 0014). Add a PyVista drape for
3D QA. Everything is written to `outputs/M1.3/`.

Acceptance criteria (docs/ROADMAP.md):
- `cop-dem-glo-30` clipped to the AOI; slope, aspect, hillshade; terrain-shadow flag for a given sun azimuth/elevation.
- Outputs in `outputs/M1.3/`; tests for slope/aspect on a synthetic plane.
- Interactive 3D QA view: `highland.viz3d.drape()` drapes any AOI raster (true-colour composite, slope, terrain-shadow flag) over the DEM with PyVista in Jupyter; vertical exaggeration is a parameter (default 1×) and is printed on the view.
- Static PNG snapshot of one 3D view saved to `outputs/M1.3/`; drape function tested on a synthetic DEM (mesh shape, CRS/extent match), no rendering in CI.

## Data (checked 2026-11-03)

- **PC `cop-dem-glo-30`** (https://planetarycomputer.microsoft.com/api/stac/v1/collections/cop-dem-glo-30): asset `data`
  (COG), gsd 30, platform tandem-x, one release dated 2021-04-22, 1°×1° items. The AOI (80.902–80.993 E) plus its horizon
  buffer crosses 81° E, so two items are mosaicked. The collection carries no `raster:bands`, so Step 1 reads the dtype and nodata from the files.
- **Product Handbook v5.0** (29 Nov 2022; https://dataspace.copernicus.eu/sites/default/files/media/files/2024-06/geo1988-copernicusdem-spe-002_producthandbook_i5.0.pdf), Table 1 and §1.2.1–1.2.3, read directly:
  - It is a **DSM** (buildings and vegetation included) from TanDEM-X/WorldDEM, with water bodies flattened.
  - Horizontal datum WGS84-G1150 (EPSG:4326); vertical datum **EGM2008 (EPSG:3855)**, metres; float32 (DGED).
  - Grid spacing 1.0″ in latitude and 1.0″ in longitude for 0–50°. That is about 30.9 m N–S and 30.7 m E–W at 6.8° N.
  - `RasterPixelIsPoint`: corner-pixel centres sit on integer degrees, and adjacent tiles share posts.
  - Accuracy: absolute vertical < 4 m LE90; relative vertical < 2 m (slope ≤ 20 %) and < 4 m (slope > 20 %) LE90; absolute
    horizontal < 6 m CE90.
- **Datum effect on derivatives:** none in practice. EGM2008 is smooth over 10 km, and slope, aspect and shadow depend only on
  height differences. Elevations are labelled "m above EGM2008" and never treated as ellipsoidal heights.
- **Target grid:** EPSG:32644. The M1.2 10 m grid is 1001 × 1001 px with its top-left corner at x 489180, y 758070, read from the
  `transform` in `outputs/M1.2/meta/*.json`. The 30 m terrain grid shares that corner (334 × 334 cells), so every 10 m pixel
  falls inside exactly one 30 m cell. Meridian convergence at λ − λ0 ≤ 0.1°, φ = 6.8° is ≤ 0.012°, so UTM grid north is
  taken as true north for aspect versus sun azimuth.
- **Sun geometry:** `outputs/M1.2/scenes_used.csv` (691 scenes) and `clear_masks/*.npz` (the same angles, in scene order).
  - Elevation = 90 − `s2:mean_solar_zenith`, as in M1.2. This matches the STAC view extension: elevation is measured from the horizon and
    azimuth clockwise from true north (https://github.com/stac-extensions/view).
  - The STAC s2 extension documents no convention for `s2:mean_solar_*`. The values agree with a clockwise-from-north azimuth:
    about 143° (SE) in late December and about 48° (NE) in June, for a 6.8° N site at roughly 10:30 local solar time.
  - Observed range in the CSV: elevation about 52.4° (late Dec/early Jan) to 69.5° (April). Step 1 records the exact
    min and max. So **self-shadow (cos i ≤ 0) needs a slope > 37.6° facing away from the sun, and cast shadow needs a
    horizon angle > 52.4°.** The geometric flag will be rare here (see D3).
- **Tile-mean versus AOI sun angles.** Each item has a `granule-metadata` asset (MTD_TL.xml; all 762 cached items have one),
  which holds a 5 km sun-angle grid. The tile 44NMN centre is about 40 km from the AOI centre. That distance is ≈ 0.36° of arc,
  so the expected error is a few tenths of a degree. Within the AOI the change is ±0.06°. Step 2 measures it (D5). The XML element
  names (`Sun_Angles_Grid`, `Mean_Sun_Angle`) are **unverified** here: PC blobs need signing, so Step 2 reads one file first.
- **Validation inputs, no new reads:** the M1.1 per-acquisition cache `outputs/M1.1/cache/s2/*.npz` at 20 m. There,
  `clear_keep2 & ~clear_base` equals SCL class 2 exactly. The M1.2 `_reflectance.tif` (B08) and `_obs.tif` files are also used.

## Design

`terrain.py` (numpy only; a function takes or returns arrays plus an odc-geo GeoBox):
- `TERRAIN_RES_M = 30.0`; `nested_geobox(fine: GeoBox, factor=3, buffer_m=0.0) -> GeoBox`. Returns a coarse grid with the same
  top-left corner, padded by `buffer_m` rounded up to whole cells.
- `load_cop_dem(aoi, geobox) -> xr.DataArray`: searches `cop-dem-glo-30`, signs the items and loads them with odc-stac onto `geobox`.
  Resampling is bilinear (D1). Output is float32 in m (EGM2008). It raises on NaN inside the buffered box.
- `horn_gradient(dem, res) -> (dzdx_east, dzdy_north)` uses Horn's (1981) 3×3 weights. Rows run north to south:
  `dzdx = ((c+2f+i)-(a+2d+g))/(8 res)`, `dzdy = ((a+2b+c)-(g+2h+i))/(8 res)`. The outer ring is NaN (D2).
- `slope_deg(dem, res)` returns 0–90°. `aspect_deg(dem, res)` returns the downslope compass direction, 0–360° clockwise from
  north: `atan2(-dzdx, -dzdy) mod 360`. It is NaN where the slope is exactly 0.
- `sun_vector(az_deg, elev_deg)` returns (E, N, Up). `cos_incidence(dem, res, az, elev)` is the unit surface normal
  (−dzdx, −dzdy, 1)/‖·‖ dotted with the sun vector. This equals cos z·cos s + sin z·sin s·cos(φ − aspect) (Riaño et al.
  2003, doi:10.1109/TGRS.2003.811693). Output is float32 in [−1, 1].
- `hillshade(dem, res, az, elev) -> uint8`: 255·max(cos i, 0), the same quantity GDAL's Horn hillshade computes. It is for display only.
- `cast_shadow(dem_buf, res, az, elev, out_slice, step_frac=0.5, z_cap) -> bool`. For each target cell it marches toward the sun
  in steps of `step_frac·res`, samples the buffered DEM bilinearly (NaN outside the buffer, never wrapped) and keeps the maximum of
  (z_k − z_0)/d_k. A cell is shadowed if that maximum exceeds tan(elev). The march stops at d = (z_cap − z_0)/tan(elev). This is the
  horizon-angle method (Dozier & Frew 1990, doi:10.1109/36.58986; Corripio 2003, doi:10.1080/713811744), done brute force
  because the grid is small. Earth curvature over 1.2 km is 0.1 m and is ignored.
- `horizon_buffer_m(z_min_aoi, elev_min, z_max_bound=2527.0) -> float` (D4). `scene_shadow(...) -> dict(self, cast, any, cos_i)`
  on the 30 m AOI grid.
- `to_fine(a30, factor=3, shape)` replicates each 30 m cell into a 3×3 block and crops to 1001×1001. It is exact because the grids nest.
- `shadow_share(valid: (t,y,x) bool, shadow: (t,y,x) bool) -> (n_shadow uint16, share float32 NaN where n_obs=0)`;
  `mean_over_valid(valid, x)` for cos i.
- `composite_shadow(npz_path, dem30, ...) -> Path` writes one window-year (resumable; the key is the npz sha256, the DEM sha256 and the parameters).

`viz3d.py` (pyvista imported lazily, ADR 0005):
- `drape_arrays(dem: xr.DataArray, layer: xr.DataArray, kind: "continuous"|"categorical"|"rgb", exaggeration=1.0) -> dict`.
  This is pure numpy and xarray. It reprojects or resamples the layer onto the DEM's grid (bilinear for continuous values, nearest for classes,
  per CLAUDE.md), raises if either CRS is missing, and returns x, y, z·exaggeration and the scalars. The CI tests target this function.
- `drape(dem, layer, kind, exaggeration=1.0, cmap="cividis", title, off_screen=False, screenshot=None) -> pv.Plotter`.
  It builds a `StructuredGrid`, always adds the text "Vertical exaggeration: N×. 3D is for viewing, not measuring", adds a scalar bar
  (or an RGB note with the display stretch) and optionally saves a PNG.

Notebook `notebooks/03_terrain.ipynb` (thin):
1. Load the AOI. Rebuild the M1.2 geobox and check that it equals the transform in `meta/*.json`.
2. Load the DEM. Print the item ids and the AREA_OR_POINT tag.
3. Show slope, aspect and hillshade maps and the slope histogram (next to ADR 0009's 15.5° median, as a sanity check only).
4. Sun table: the range of sun angles; the MTD_TL check (D5).
5. Pilot the lowest-elevation scene: maps of self, cast and any shadow; step-size convergence (D4).
6. Loop over the 43 window-years and write the summary.
7. Diagnostics (see Science checks).
8. With/without table.
9. 3D QA: drapes and PNG, each paired with its 2D map.
10. README.

`outputs/M1.3/` (git-ignored):
- `dem_30m_buffer.tif` (float32, m EGM2008).
- `terrain_30m.tif`: bands dem, slope_deg, aspect_deg, hillshade_315_45 (float32).
- Per window-year `s2_<sy>_<WIN>_shadow.tif` (10 m, float32): bands `shadow_share`, `n_shadow`, `cos_i_mean`, `cos_i_min`,
  with NaN where n_obs = 0 or outside the AOI.
- `scene_shadow.csv` (per scene: AOI shares of self, cast and any shadow; share of valid observations shadowed; SCL-2 overlap).
- `shadow_summary.csv` (per window-year: share of AOI pixels flagged under D6 and with any shadow, mean share, cos i percentiles).
- `with_without_flag.csv`, `sun_grid_check.csv`, `drape_<layer>.png` and a README with the environment.

No new packages in `environment.yml`. scipy, xarray-spatial and richdem are not needed. xarray-spatial 0.10.20 (Oct 2026) would pull in numba, and its
`shadows=True` needs CuPy/rtxpy. richdem's last release is 0.3.4 (2018) with no cp313 wheel. Horn plus a ray march is about 80 lines of tested numpy.

## Science checks

- **Terrain gotcha.** Shadow is computed per scene from that scene's own angles and then aggregated per composite. No single angle
  is ever applied to a composite. Results are reported with and without the flag.
- **Aggregation.** `with_without_flag.csv` gives the AOI median, p01 and p99 of NDVI, NBR and NDMI per window-year for all pixels and for unflagged pixels,
  plus the flagged share. M1.6 and M1.7 carry both columns.
- **Valid set.** The masks keep SCL class 2 (ADR 0012), so shaded observations are in the denominator, as they should be.
- **Grids.** Derivatives use the 30 m grid that nests in the M1.2 grid. No 10 m slope is invented (D1). The DEM is resampled bilinearly,
  classes and flags with nearest. PixelIsPoint is handled by GDAL. Alignment is checked from data: the 10 m-pixel shift that
  maximises the correlation between composite B08 and `cos_i_mean` over ±3 px (SWM 2023, NEM 2023) should be 0 if the
  horizontal accuracies hold (DEM < 6 m CE90). The shift is reported, not tuned.
- **SCL class 2 diagnostic** (per scene, split by era < 04.00 versus ≥ 04.00, per ADR 0010/0012): P(modelled shadow | SCL 2), P(SCL 2 | modelled
  shadow) and the chance level (the AOI share of each). The comparison is made at 10 m by replicating the 20 m SCL. It is a
  diagnostic, not a calibration. Before 04.00, class 2 also holds dark soil and burns.
- **Illumination diagnostic.** Composite B08 and NDVI binned by `cos_i_mean`, for SWM 2023 (NE sun) and NEM 2023 (SE sun). The plot
  is captioned as confounded by land cover, which is not masked until M1.4.
- **Land cover.** Not applied. **Clouds.** The thin flags from M1.2 are carried into the summary.

## Tests (no network unless marked)

- `test_terrain.py`:
  - Planes z = p·x + q·y on a 30 m grid. Slope atan(√(p²+q²)) to 1e-5°. Aspect 90 for a plane descending to the east, 180 for
    one rising to the north, and the diagonals 45/135/225/315. A row-order sign test. Flat ground gives slope 0 and aspect NaN.
    The ring is NaN, and the interior is exact on planes.
  - cos i is 1 for a facet normal to the sun. A flat surface gives sin(elev). Facing away at slope 90 − elev + 1° gives < 0. Elevation 90 equals cos s.
  - Hillshade is 0–255.
  - `cast_shadow`: a wall of height H on flat ground casts a shadow of length H/tan(elev) (± one step) for sun azimuths 90, 135 and 270.
    Elevation 89.9° gives no cast shadow. Nothing is read across the far edge (no wrap). The `z_cap` early stop matches the uncapped result.
  - `horizon_buffer_m` matches the hand calculation. `to_fine` works on 1001 px (not a multiple of 3). `nested_geobox` corners line up.
  - `shadow_share` for n = 0/1/2/3/4, and the D6 cut at even n.
- `test_viz3d.py`:
  - `drape_arrays` on a synthetic 20×30 DEM: point count 600; z = dem·exaggeration; a 10 m layer is resampled to the DEM shape
    (nearest keeps class values); a CRS mismatch is reprojected and a missing CRS raises; the extent matches.
  - Plotter construction: `importorskip("pyvista")`, `off_screen=True`, no screenshot. Skipped in CI.
- `@pytest.mark.network` (`test_terrain_network.py`):
  - The DEM over the AOI is finite, float32, EPSG:32644 at 30 m, and its corner equals M1.2's.
  - Its values equal a rasterio `reproject` of the same items with bilinear resampling, to float tolerance. This is the same kind of check as M1.2.
  - One MTD_TL.xml `Mean_Sun_Angle` equals the item's `s2:mean_solar_*`.

## Decisions needed (→ ADR 0015 DEM/derivatives, ADR 0016 shadow flag; amendments to 0014 and possibly 0005)

- **D1 Grid.**
  - (a) DEM bilinear to 30 m UTM nested in the 10 m grid; derivatives and shadows at 30 m, replicated to 10 m.
  - (b) DEM to 10 m first. On an interpolated surface a 3×3 Horn window spans 20 m, less than one source post, so it gives
    stripe artefacts and no new information. Cast shadows would cost 9× as much.
  - (c) Native geographic grid. Spacing is anisotropic, and aspect would need reprojecting (wrap at 360°).
  - Bilinear versus cubic: cubic can overshoot at breaks; bilinear smooths peak slopes slightly. It is the same method as ADR 0009.
  - **Recommend (a) with bilinear.**
- **D2 Derivatives and edges.** Horn versus Zevenbergen–Thorne. GDAL says ZT suits smooth landscapes; these hills are not smooth.
  The outer ring is NaN, and the DEM is buffered, so the ring never reaches the AOI. **Recommend Horn in plain numpy.**
- **D3 Shadow definition.**
  - (a) Geometric only: self (cos i ≤ 0) ∪ cast. It has no free parameter. At an elevation of 52°+ it is expected to flag little.
  - (b) Add a low-illumination cut on cos i or on cos i / cos z. Any number (for example "half the flat-ground direct beam") is an
    assumption this data cannot ground without per-scene reflectance, which ADR 0014 avoided.
  - (c) Calibrate a cut from the illumination diagnostic. That is calibration against confounded data.
  - **Recommend (a) as the binary flag, plus continuous `cos_i_mean` and `cos_i_min`** so that M1.6 can test sensitivity. Defer any cut
    until it can be judged against the disturbance threshold.
- **D4 Horizon buffer and step.**
  - Buffer W = (z_max − z_min,AOI)/tan(elev_min). z_max = 2527 m is Sri Lanka's highest point (Pidurutalagala: 2524 m on
    Wikipedia, 8292 ft from the Survey Department; the larger value is used). With z_min ≈ 1044 m (ADR 0009) and elev_min ≈ 52.4°,
    W ≈ 1.14 km, rounded up to whole 30 m cells at runtime. No terrain beyond W can shade the AOI.
  - DSM canopy adds at most tens of metres, which the runtime z_min absorbs.
  - Step: 0.5 cell. The pilot compares steps of 1, 0.5 and 0.25 cell and reports the change in shadow share.
  - **Recommend.**
- **D5 Sun angles.**
  - (a) Tile mean from `scenes_used.csv` (the ADR 0014 contract). (b) Per-scene AOI-centre values from the MTD_TL grid.
  - Derived criterion: keep (a) if max(|Δz|, |Δφ|·sin z) over the scenes is below the slope noise implied by the DEM. That noise is
    σ_slope ≈ 0.433·σ_z/res for Horn with uncorrelated errors; σ_z = LE90/1.645 gives ≈ 1.0°–2.0°. Uncorrelated errors are a pessimistic proxy.
  - Measure all 691 scenes if the 10-scene pilot of the MTD_TL fetch is fast. Otherwise measure the scenes with min and max elevation and azimuth per window.
  - **Recommend (a), conditional on the measurement.**
- **D6 Composite flag cut.** `shadow_share ≥ 0.5`: if shadowed observations are darker, the median then is (or averages in) a
  shadowed value. For odd n that holds when s > n/2, for even n when s ≥ n/2. This is logic, not tuning. `shadow_share > 0` ("any") is reported too.
  **Recommend ≥ 0.5 as the flag.**
- **D7 Display hillshade.** (a) The GDAL cartographic convention, azimuth 315° (GDAL's documented default) and altitude 45°
  (not confirmed from the page fetched). (b) The median scene sun. **Recommend (a), labelled display-only.** The analysis uses per-scene cos i.
- **D8 ADR 0014 amendment.**
  - ADR 0014 says the masks are "SCL clear, all bands non-zero". It omits the ADR 0012 keep-set {2, 4, 5, 6} and the forced source
    nodata 0 that makes the non-zero test valid for the 20 m bands. ADR 0013 shows the 43 mask files were byte-identical after the fix.
  - Its "50–100 kB" agrees with the measured 2.8 MB / 43.
  - **Recommend an appended, dated "Amendment (M1.3)" section** that corrects the definition, records that M1.3 implemented the flag and
    links to ADR 0016. The original text is not rewritten.
- **D9 Off-screen PNG.** Step 0 probes `pv.Plotter(off_screen=True).screenshot()` and `pv.Report()` (render window class).
  - (a) Use as-is. VTK ≥ 9.4 wheels select OSMesa/EGL at runtime (https://docs.vtk.org/en/v9.4.2/advanced/available_python_wheels.html);
    the conda-forge build behaviour is unverified.
  - (b) Pin an OSMesa build of conda-forge `vtk` in `environment-3d.yml` (amends ADR 0005).
  - (c) Use `xvfb-run` if the system already has it.
  - (d) The owner renders the PNG locally.
  - **Recommend (a) → (b) → (d).** No matplotlib stand-in, because the criterion names PyVista.

## Risks

- **DSM, not terrain.** TanDEM-X saw the canopy of 2011–2015. Stand edges of 20–30 m height create false slopes and canopy cast
  shadows, and stands opened since still appear raised. The flag mixes terrain and old canopy. This is stated in ADR 0015 and the README.
  Slope in Module C needs a DTM decision later.
- **Rare geometric flag.** At these sun elevations the flag may fire on well under 1 % of the AOI. The continuous cos i layers then
  carry the illumination effect, and "with/without" may differ little. That is a result, not a bug.
- The 30 m flag is blocky at 10 m. Bilinear smoothing lowers extreme slopes, so self-shadow may be under-flagged slightly.
- The M1.1 cache is described as "safe to delete". If it is missing, the SCL-2 diagnostic must reread SCL (about 15 min, per M1.1).
- **Cost (estimates; the pilot measures them).**
  - DEM: two COGs, about 1 min.
  - Shadows: about 0.11 M cells × ≤ 80 steps per scene, about 0.3 s × 691 scenes ≈ 3–6 min.
  - Aggregation: 43 files, less than 1 GB RSS (the largest window is 39 × 1 Mpx bool).
  - MTD_TL fetch: unknown, piloted.
  - Disk: about 100–300 MB, mostly the float32 shadow COGs.

## Step 0 probe results (2026-11-03) and Deviations

Approved by the owner on 2026-11-03 with D1-D9 as written. Probed with the pinned env (GDAL 3.13.3, rasterio 1.5.2).

Verified items:
- **DEM items.** Two items cover the AOI plus buffer: `Copernicus_DSM_COG_10_N06_00_E080_00_DEM` and `..._E081_00_DEM`.
  Each is 3600 x 3600 float32, deflate COG, EPSG:4326, spacing 0.000277... deg (1 arc-second), no nodata value declared.
  Both carry the same `datetime` 2021-04-22. The 81 E seam is at UTM x = 500000 m, 810 m east of the AOI edge (x 499190), inside the buffer.
- **PixelIsPoint.** Both files carry `AREA_OR_POINT=Point`. GDAL's default reading shifts the geotransform by half a pixel:
  the origin reads 80.99986111 (not 81.0), i.e. the corner of the area represented by the corner post. With
  `GTIFF_POINT_GEO_IGNORE=TRUE` it reads 81.0. The STAC `proj:transform` agrees with the default (80.99986...).
  odc-stac and rasterio therefore handle PixelIsPoint correctly with defaults, matching the Product Handbook (posts on integer degrees). No code change.
- **MTD_TL.xml.** The `granule-metadata` asset (signed blob) parses with `Sun_Angles_Grid/{Zenith,Azimuth}` -> `COL_STEP`,
  `ROW_STEP` (5000 m), `Values_List/VALUES` (space-separated rows), and `Mean_Sun_Angle/{ZENITH_ANGLE,AZIMUTH_ANGLE}`
  (deg). Geocoding comes from `Tile_Geocoding`: `HORIZONTAL_CS_CODE` (EPSG:32644), `Geoposition resolution=10/ULX,ULY` (399960, 800040).
  The element names in the plan are confirmed. `Mean_Sun_Angle` equals the item's `s2:mean_solar_*` (checked on one item; the network test repeats it).
- **GDAL hillshade defaults.** `gdaldem hillshade --help` (GDAL 3.13.3) lists azimuth default 315 and altitude default 45. D7(a) stands.
- **VTK off-screen.** The conda-forge env resolves vtk-base 9.7.1 with pyvista 0.49.1. Plain `Plotter(off_screen=True).screenshot()` **fails**
  here: `pv.Report()` shows "Render Window: error", VTK tries X (no DISPLAY), then EGL (no device) and then OSMesa
  ("libOSMesa not found"). conda-forge has no OSMesa vtk build (`micromamba search "*osmesa*"` finds nothing on linux-64),
  so D9(b) is not available. `xvfb-run -a python ...` renders fine (vtkXOpenGLRenderWindow, GLX software), and `xvfb-run` exists on this system. D9(c) is used.

Deviations:
1. **D9: option (c) instead of (a) -> (b) -> (d).** (a) fails and (b) does not exist on conda-forge, so the PNG is rendered
   with `xvfb-run -a` (one of the approved D9 options). The notebook and README say so; ADR 0005 gets an appended note. Not a change to
   any other D-decision. On a desktop with a display, `Plotter(off_screen=True)` needs no wrapper.
2. **Self-shadow threshold in the plan text is wrong.** Plan says self-shadow needs "a slope > 37.6 degrees facing away from the sun".
   For a facet facing directly away, cos i = cos(zenith + slope) <= 0 needs slope >= 90 - zenith = the sun **elevation**, so the slope must exceed
   52.4 degrees (the minimum elevation), not 37.6 (which is the zenith). The same mistake is in the test line "slope 90 - elev + 1 deg". The tests
   use elevation + 1 deg. This makes the geometric flag even rarer than the plan expected; D3 is unchanged (the logic of the decision
   depends on rarity, and the continuous cos i layers carry the illumination effect).
3. **Third 3D env name.** The optional 3D layer was installed as a separate env `highland-3d` (environment.yml + environment-3d.yml solved together
   with `micromamba create`) rather than on top of `highland`, so the main env that produced the M1.2 outputs and `environment.explicit.txt` is untouched.
4. **Network test tolerance.** The plan says the odc-stac DEM equals a rasterio `reproject` "to float tolerance". Measured: max difference 0.069 m
   (71 % of cells differ by more than 1e-3 m; values ~1000 m), so the test tolerance is 0.1 m, about 40 times below the DEM's relative vertical accuracy
   (2 m LE90). Cells within 100 m of the 81 E tile seam are excluded from the comparison.
